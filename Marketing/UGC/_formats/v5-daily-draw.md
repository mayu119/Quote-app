# v5-daily-draw — 型5フォーマット仕様

- 最終更新: 2026-08-21
- 参照: `~/knowledge/growth-knowledge/ugc-acquisition.md#CTA包含度による投稿構造の分類`、`apps/wordsforme.md#CTA包含度5類型によるWFM全投稿の棚卸し (2026-08-21)`、Linear P-629
- 位置づけ: 現行標準 `v3-lineart-7list-cvnative`(型3)と**併走**する転換枠。型3を置き換えない。

## 型3との決定的な違い — 「誰が喋っているか」

型3と型5の差は、WFMをスライドの何枚目に置くかではない。**投稿の話者が誰か**である。

| | 型3(現行) | 型5(v5) |
|---|---|---|
| 話者 | 編集者・一般ユーザー | **Words For Me 自身** |
| WFMの登場 | 7項目のうち1項目 | 全スライドが製品の画面言語 |
| 想起の希釈 | 1/7 | 1/1 |
| 名言の役割 | 締めの装飾 | **コンテンツ本体** |
| 視聴者の体験 | 「いい習慣リストを読んだ」 | **「アプリを1回使った」** |

## 広告にならない理由 — 型5は「紹介」ではなく「実演」

型5を素直に作ると「アプリ紹介スライド」になり、既存の禁止判断(専用紹介カード・機能説明・DLボタンの禁止)に抵触する。回避策は、**アプリを説明せず、アプリの出力をそのまま出す**こと。

- 「〜という機能です」が1文字も要らない。実演しているので説明する対象がない。
- 専用アプリ紹介カードを置かない。全スライドがそれなので、置くと二重になる。
- **実画面の合成をしない**。WFMのデザイントークン(`DesignSystem.swift`)でスライドをネイティブに描画する。合成ではないため、2026-08-16に発生した「別アプリに見える」失敗が構造的に起きない。

## スライド構成

製品の実フロー(`DailyDrawView` → `もう少し読む` → `今週の棚`)をそのままスライドにする。

### v5a(Original名言・全9枚) — 初期採用形

| 枚 | 役割 | 中身 | データ源 |
|---:|---|---|---|
| 1 | 表紙 | 状況の名指し + 伏せカード | 手書き(状況コピー) |
| 2 | 引く直前 | 一人称の日記調1行。期待を宣言口調で説明しない | 手書き |
| 3 | **名言** | カードをめくった状態 | `quote_ja` |
| 4 | 言い換え | 自分ごとへの翻訳 | `punchline` |
| 5 | もう少し読む | 誰のための言葉か | `meaning_preview` |
| 6 | 効く瞬間 | どの夜に出てくる言葉か | `push_notification_hook` |
| 7 | 棚に残す | 「今日をひとことで置いていく」メモ画面 + 一人称1行 | 手書き |
| 8 | 私の棚 | `WeeklyShelfView` の構造(見出し + 週の説明行 + `punchline` の行リスト)を枠の視覚言語で | `quotes_full.json` から**同カテゴリー**3枚 |
| 9 | 締め | Words For Me + アイコン。DLボタンなし | 固定 |

### v5b(実在著者・PD限定・全10枚) — 著作権判定を通した場合のみ

v5aの3枚目のあとに「著者(`author_kana` / `author_description` / `author_fact`)」と「出典(`source_context`)」を挿入する。情報価値は上がるが、**型5は名言がコンテンツ本体になるため、型3より著作権リスクが高い**。既存判定(詩歌はPD限定、散文引用は攻め)を型5ではより厳しく適用する。初期3本はv5aで回す。

## バリエーション軸 — 型5のスケーラビリティ源

型5が続くかは、バリエーション軸が製品側に既にあるかで決まる。WFMは6軸を内蔵している。

| 軸 | 母数 | 使い方 |
|---|---:|---|
| 名言 | 300枚(Original 167 / 実在 133) | 1枚=1本 |
| 中カテゴリー | 10種×各30枚 | 「愛とつながり」の棚から、等 |
| 状況(お題) | 事実上無限 | 返事が来ない夜 / 面接の朝 / 親と喧嘩した日 |
| 著者 | 実在133本 | v5bのみ |
| 深さ | `meaning_preview` / `meaning_premium` | **投稿はpreviewで止める**(下記) |
| 時間帯 | 今日の一枚 / 夜の言葉 | 製品に既存の2モード |

Original 167枚 × 状況 だけで当面枯れない。台本テンプレは1つで、差し込むデータは `quotes_full.json` から引く。

## 表紙の組み方（2026-08-21 確定）

**1枚目に置く文字はタイトルだけ。** 英文小見出しもサブコピーも置かない。

- **横書き**（`wfm_render.h_title`）。縦書きは `H*0.42` の箱に長い見出しを詰めるため字送りが痩せる。22字の見出しで **縦書き61px → 横書き72px（1.18倍）**。
- 配置は型3の勝ち構図に揃える: **線画=上（0.12H〜） / タイトル=中下（0.585H） / 下25%は空ける**。
- 英文小見出しは2枚目以降の枠スライドでは使ってよい。表紙だけ外す。

## 棚スライドは実画面の構造で描く

**カードのサムネイルを並べない。** `WeeklyShelfView.swift` の実画面は `punchline` のテキスト行が縦に積まれたリストであり、カードが並ぶ画面はアプリに存在しない。並べると (1) 型5の「実画面の合成をしない」に抵触し、(2) カードが200px幅まで縮んで名言が読めなくなる。

**採るのは構造だけ。見た目は採らない。** 実画面のUI言語(ダーク地・角ゴ・角丸パネル)でそのまま描くと、棚の1枚だけがデッキから浮く(2026-08-21 Mayu指摘)。棚は**枠の層**として扱い、生成りオフホワイト＋墨色明朝で描く。行の区切りは角丸パネルではなく罫。

- 説明行「今週は「◯◯」の言葉をN枚集めました。」の `◯◯` は `Quote.swift` の `displayTitleJa`。**棚に並べる名言は全部このカテゴリーに揃える**(混ざると説明行が実データと食い違う)。`shelf()` は混在を `assert` で弾く。
- 説明行は折らずに1行へ収める。折ると「3枚集めま／した。」のように語中で割れる。
- 行が `SAFE_BOTTOM` へ届いたら `assert` で落とす。実画面はスクロールできるがスライドはできない。

## 線画の下限 — `SAFE_BOTTOM = 0.72`

**線画を 0.72H より下に出さない。** TikTokはキャプション・ユーザー名・操作UIが下25%に乗るため、下揃えのまま敷くと絵が隠れる。

`wfm_render.lineart(path, dy=...)` で上へ送る。送り量は `wfm_render.ink_bounds()` で実インクの上下端を測って算出し、目分量で決めない（生成物ごとに余白が違う）。

## 制作パイプライン — 型3より軽い

型3は毎回 gpt-image-2 で線画9枚を生成していた。型5は**背景画像の生成が不要**で、デザイントークンによる描画のみ。

```
quote_id + 状況コピー → quotes_full.json から6フィールド取得 → PILでWFMトークン描画 → 9枚
```

- 出力: `slides/` 1080x1920 PNG → `export-tiktok-1080x1920/` JPEG（`render.py` の `build()` → `export()` → `contact_sheet()`）
- 色: `PageBase` / `TextPrimary` / `TextSub` / `AccentRose`(`DesignSystem.swift` の実値に合わせる)
- 書体: ヒラギノ明朝 ProN(製品のserifトークンに対応)
- 1本あたりの手作業は「状況コピー1行 + 棚メモ1行」のみ。**バッチ生成できる**。

## 禁止事項

- `meaning_premium` を投稿に出さない。かつ**その存在に言及しない**。「続きはアプリで」等は宣言口調にあたり、2026-08-17のwithhold失敗の再来になる。6枚目で自然に終える。
- 機能説明、専用アプリ紹介カード、DLボタン、実画面の合成。
- 未確認の人気・効果の断定(「一番保存されている言葉」等)。保存数の実測が取れるまで使わない。
- 同じ状況コピーの再放送。状況は台帳の `situation` に記録して重複を避ける。
- 表紙にタイトル以外の文字(英文小見出し・サブコピー)を置く。表紙の縦書きタイトル。
- 線画を `SAFE_BOTTOM`(0.72H) より下に出す。
- アプリに無い画面を作る(カードを並べた棚など)。実装を読んでから描く。

## 台帳変数

```json
{
  "format_version": "v5a-daily-draw",
  "cta_containment_type": 5,
  "quote_id": "<quotes_full.json の id>",
  "situation": "<状況コピー>",
  "theme_category": "<category>",
  "total_slides": 9,
  "lane": "product-native",
  "appeal_mechanism": "demonstration"
}
```

`cta_containment_type` はフック家系(`title_type`)や訴求メカニズムと**独立変数**として記録し、混ぜない。
